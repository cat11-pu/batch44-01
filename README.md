# GSB Bugfix Task
## 题面
排位赛季第二天，论坛上全是五排车队碾压单排的录屏，策划把匹配日志拉出来一看，问题比投诉还多。五人预组队按队内平均分入池，实际强度按最高分算，一个低分小号就能把整队拉进鱼塘；队内最高与最低差两千分也照配，进游戏三分钟就被推平；匹配重试把同一张票据塞进两个对局，玩家收到两条进游戏通知，后开的那局直接判负；分数用整数除法取整，青铜到白银全落在同一档，高分段反而挤在一起；新号默认一千分，前二十局完全不收敛，老玩家被当成新手陪练；队伍换人以后分数缓存没失效，新队员按旧队伍分匹配；等待超过三分钟就无上限放宽区间，最后配到跨三个大段；单排、双排、五排混在一条队列里按人数加权，五排永远吃单排；补位玩家按个人分而不是队伍分计算，补进来的高分选手拉不动队伍；取消匹配后票据仍留在池里，还是被拉进对局，进去就记一场失败；深夜人少时同一批人反复互相匹配，连续五局都是同一个对手；跨服标记和语音偏好没有参与匹配维度，同队玩家互相听不见。party_mmr_balancer.py 的 PartyMmrBalancer 负责票据、入池、区间放宽和出票，所有决策都要留一份可回放的快照。两条硬性约束：同一队伍同一时刻只允许一张活动票据，重复入队报 MM_TICKET_DUP；区间放宽必须有硬上限，段位差超过一个大段按 MM_RANGE_OVERFLOW 拒绝出票。第三条是出票结果必须可复算，给定票据和分数快照要能重现同一对局，不可复算按 MM_NONDETERMINISTIC 失败。今晚要开新赛季，匹配参数不能大改，只能修。

## 运行方式

```bash
python -m pytest tests -q
```

# GSB Bugfix Task
## 题面
世界首领开放分线之后，玩家在跨线传送时频繁掉进虚空，运维把分线监控和战斗日志摆在一起看，发现合并时段的问题最集中。分线人数按登录数统计，实际在线早空了，热点线却一直排队；切线之后宠物和召唤物留在原线，角色成了光杆；首领刷在即将合并的线上，合并完成首领直接消失；玩家手动切线绕过战斗锁定，残血瞬移脱战，竞技场里已经有人这么用；满员阈值写死，不考虑区域热点和任务密度；合线时同名 NPC 出现两份，对话触发两次；跨线组队队友互相看不见，也吃不到彼此增益；分线编号复用，旧线残留实体挂到新线，NPC 顶着别人的名字；挂机角色占线，活跃玩家进不来；切线冷却太短，玩家来回跳线刷资源；世界事件进度按线独立计算，切线后进度倒退；分线满员后新玩家排队，界面却显示可以进。zone_shard_balancer.py 的 ZoneShardBalancer 管分线容量、合并和实体迁移，玩家、召唤物和场景实体要一起搬。分线、实体和玩家三方要有一致性检查，合并前后各跑一次，差异超过阈值就中止并保留现场供复盘。合并这块立三条硬线：合并前必须冻结目标线实体生成并迁移全部玩家与召唤物，遗漏按 SHARD_ORPHAN 失败；战斗、副本、交易状态的玩家不得被切线，强制切线按 SHARD_BUSY_EVICT 拒绝；分线编号必须单调不复用，复用按 SHARD_ID_REUSE 中止合并。合并前后各留一份实体清单给运维比对。周六世界事件，分线合并要能扛住峰值。

## 运行方式
```bash
python -m pytest tests -q
```

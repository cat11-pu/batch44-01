# GSB Bugfix Task
## 题面
播放器切到硬件解码之后，四 K 片源在快进时花屏，低端机上还会把界面卡住十几秒，用户以为应用崩了直接卸载。解码表面复用太快，上一帧还在显示就被写入；表面池耗尽后阻塞主线程，界面直接卡死；分辨率切换后池没重建，画面整片花；十位内容按八位表面解码，渐变出现色带；解码器 flush 之后旧表面没释放，内存一路涨；多路视频共用同一个池，互相把对方的帧踢掉；硬件解码失败静默回退软解，CPU 直接打满；表面格式和渲染器期望不一致，颜色整体错；seek 之后关键帧之前的表面被当成有效帧，快进必花；解码线程和渲染线程没有同步，偶发绿屏；池大小写死，高码率片源根本不够用，四 K 一开就排队；播放结束表面没归还，下一次播放黑屏。gpu_decode_surface_pool.py 的 GpuDecodeSurfacePool 管表面生命周期、池容量、背压和格式，解码器重建时表面引用要一起清。表面编号、引用计数和帧号要能串起来查，花屏时能定位到具体哪一次复用，以及哪个线程写的。三条硬门禁：表面在渲染消费前不得复用，复用冲突按 DEC_SURFACE_REUSE 失败；池耗尽必须背压而不是丢帧或阻塞界面，背压信号要能传到上层播放器，阻塞超过十六毫秒按 DEC_POOL_STALL 失败；分辨率、位深或格式变化必须重建池和解码器，未重建按 DEC_FORMAT_STALE 失败。这版要上电视端，内存峰值也要压到验收线以下。卡界面是要被打回的。

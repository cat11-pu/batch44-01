# GSB Bugfix Task
## 题面
运营接入第三方账号登录以后，客服陆续收到账号被陌生设备接管的投诉，安全组在绑定表里发现了同一个邮箱挂了三条外部身份。绑定只比对邮箱，不要求邮箱已验证，攻击者注册一个同邮箱的外部账号就能接管；绑定令牌用过一次还能再用，链接转发给同事也能绑上；已经登录的会话可以直接发起绑定，不需要重新输入密码或者二次验证；解绑以后旧会话仍然有效，退出重登才失效；同一个外部身份标识在两个租户下被当成同一个人，A 租户的绑定能登进 B 租户；并发绑定同一账号产生两条记录，登录时随机命中一条；第三方返回的邮箱没有验证状态也照单全收；账号被停用或者注销以后绑定关系还留着，恢复账号就被陌生身份直接登入；绑定回调不校验 state，攻击者构造链接把自己的外部账号绑到受害者名下；解绑最后一个登录方式后账号再也登不进去；第三方侧注销账号，本地绑定没有撤销，仍然可以换发会话；绑定和解绑没有审计字段，出了事查不到操作人和时间。identity_link_broker.py 的 IdentityLinkBroker 管外部身份登记、绑定校验和解绑吊销，外部身份以提供方加主体标识作为唯一键。四条底线：绑定前必须确认邮箱已验证且用户完成重新认证，缺一按 LINK_UNVERIFIED 拒绝；同一提供方主体全局只能绑定一个本地账号，重复按 LINK_DUP_SUBJECT 拒绝；解绑必须吊销该账号全部会话，并保证至少保留一种登录方式，否则报 LINK_LAST_FACTOR；所有绑定变更写审计流水，缺操作者或时间按 LINK_AUDIT_GAP 拒绝。合规那边下周要看账号接管的风险评估，先把邮箱抢占和解绑吊销两条堵上。

## 运行方式
```bash
python -m pytest tests -q
```

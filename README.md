# GSB Bugfix Task
## 题面
装备强化改版上线后，客服后台的强化申诉一晚上堆了六百条，运营把强化记录和材料流水拉出来逐条核对。保底计数挂在角色身上而不是装备实例上，换一把武器接着上次的失败次数，第一发就触发保底；连续失败十次界面显示必成，实际成功率还是原值；成功之后计数没有清零，下一件装备第一次强化就白送一级；保护符放在背包里没扣，失败也没掉级，玩家把保护符当免费保险；两件装备同时点强化，强化石只扣了一份，两件都升了一级；等级已经到顶还继续吃材料，多出来的材料凭空消失；失败降级以后面板攻击没有重算，重登才恢复；客户端自己算成功率和结果，改包就能指定成功；强化到一半断线，材料扣了等级没动，也没有回滚记录；同一个请求因为网络重试扣了两次材料；账号绑定的装备强化后变成可交易，直接挂拍卖行；强化石等级低于装备要求也能放进去。gear_refine_pity.py 的 GearRefinePity 管材料扣除、保底计数和等级变更，强化石、保护符、装备实例三者的绑定关系写在配置里。三条门禁必须守住：扣材料和改等级在同一个事务里完成，中途失败整体回滚，出现半扣半升按 REFINE_PARTIAL 失败；保底计数按装备实例记，成功即清零，计数与实例对不上报 REFINE_PITY_DRIFT；成功率和降级规则只认服务端结果，客户端上报的结果一律按 REFINE_CLIENT_TRUST 拒绝。运营今晚要发补偿名单，先把材料账对平。

## 运行方式
```bash
python -m pytest tests -q
```

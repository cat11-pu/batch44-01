# GSB Bugfix Task
## 题面
银行客户端把 ID 令牌改成加密格式后，一部分用户登录失败，另一部分却接受了被改过的令牌。客户端团队换了加密库，服务端还在按明文令牌的习惯处理，密钥轮换窗口也没跟着调整。密钥管理算法允许 none 和 dir，策略要求 RSA-OAEP 也照收；内容加密接受 A128CBC-HS256，而基线只允许 A256GCM；kid 对不上时遍历所有密钥试解，轮换期直接放大攻击面；密文被截断仍按原长度解，认证标签不足也继续；保护头没有参与认证，改算法字段也能解出明文；zip 压缩没有解压上限，一个令牌能把内存吃满；解密后才校验签发者和受众，错误信息还区分失败阶段；旧密钥到点立刻删除，在途令牌全部解不开；多个接收方复用同一个内容密钥；ECDH-ES 的临时公钥不验曲线点，非法点也进派生；嵌套 JWT 只解密不验内层签名；时钟偏差留零秒，正常令牌被判过期。oidc_jwe_decryptor.py 的 OidcJweDecryptor 负责算法白名单、密钥选择、密钥轮换窗口和声明校验。算法或加密方式不在白名单必须回 JWE_ALG_DENIED；认证标签失败不得返回任何明文，也不能区分填充错误，统一报 JWE_AUTH_FAILED；解出的声明仍要校验签发者、受众和有效期，失败按 JWE_CLAIMS_INVALID 拒绝并返回统一错误。手机银行每天几百万次登录，谁也不敢先关加密开关，运维要求先把解密失败率降下来。

## 运行方式
```bash
python -m pytest tests -q
```

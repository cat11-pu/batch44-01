# GSB Bugfix Task
## 题面
出口防火墙升级状态检测后，办公网出现一半连接被误杀，扫描流量却能穿过。运维把抓包和表项导出对比，发现状态机和回收逻辑各说各话，连接跟踪表在高峰期十分钟就翻一倍。没有三次握手的 ACK 也能建 ESTABLISHED 表项；窗口外的 RST 直接把正常连接拆掉；首片建状态，后续分片完全绕过检查；ICMP 差错报文不匹配内层五元组，随便一个不可达就把连接清了；表满时淘汰最老的活跃连接，长连接集体断；UDP 流只按目的地址匹配，任意源端口都能收到回包；FTP 和 SIP 的 ALG 开了针孔却从不回收；TIME_WAIT 复用后旧报文能混进新连接；SYN 之后的 ACK 不校验序号，伪造确认也能过；NAT 端口分配撞车时覆盖已有映射，用户被串流；接口 down 后表项不删，恢复后流量仍走旧路径；没有按租户限额，一个扫描器就能把整张表打满。表项导出后还发现同一条流在两个方向各占了一项。conntrack_state_guard.py 的 ConntrackStateGuard 负责状态建立、协议匹配、ALG 和回收。非 SYN 且无现有状态的报文必须丢弃并记 CT_INVALID；表满只能先回收过期和关闭态，仍满时对新流回 CT_TABLE_FULL，不能清掉已建立连接；ICMP 差错必须匹配内嵌五元组和方向，否则按 CT_ICMP_MISMATCH 丢弃。办公网和视频会议都走这台设备，谁也不敢直接重启。

## 运行方式
```bash
python -m pytest tests -q
```

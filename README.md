# GSB Bugfix Task
## 题面
清洗中心用 BGP FlowSpec 下发限速规则，上周一条畸形规则把客户整个网段黑洞了半小时。这条规则是运维用脚本生成的，组件顺序和动作字段都没经过模板校验，事后只能从路由器日志里一点点还原，规则模板里连动作顺序都没有约束。组件类型和长度不校验，解析越界读到下一段；重叠规则不按精确度排序，宽规则压过细规则；discard 和 rate-limit 同时出现时动作顺序随机；重定向到不存在的 VRF 也下发，流量直接丢；前缀长度零被接受，等于指向全网；没有路由目标约束的规则泄漏到其他 VRF；规则撤销只删一个组件，残留动作继续生效；过期规则没有时间戳，撤销消息丢了就永久生效；分片标志位被忽略，非首片绕过匹配；TCP 标志按任意一位命中，误伤正常握手；规则计数器不区分方向，无法判断是否命中；同一前缀多条规则并发更新，最后写入的覆盖前一条。flowspec_rule_guard.py 的 FlowspecRuleGuard 负责规则解析、冲突消解、撤销和生命周期维护。前缀长度为零或越界必须拒绝并报 FSPEC_PREFIX_INVALID；同一规则内动作冲突不得后者覆盖，直接回 FSPEC_ACTION_CONFLICT；撤销必须原子移除全部组件，残留按 FSPEC_ORPHAN_ACTION 告警并清理，告警要带规则编号和来源邻居。客户已经发来索赔函，清洗中心今晚必须给出规则审计，否则下一次割接还会重演。

## 运行方式
```bash
python -m pytest tests -q
```

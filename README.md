# GSB Bugfix Task
## 题面
成就系统接上新埋点以后，运营后台看到同一个成就一天解锁四万次，补偿邮件把玩家邮箱撑得打不开，论坛上已经有人卖刷成就的服务。同一场战斗结算两次，击杀计数加了两遍，成就在第二遍直接解锁；账号共享成就只有主角色涨进度，小号打满两千点也不触发；隐藏成就的名字和达成条件在成就列表接口里提前露了出来，攻略站当天就抄走；两条子条件本来配的是或关系，求值时按与处理，只满足一条就发奖；数据修正把进度从一百改回八十，界面仍显示已完成，奖励也照留；限时成就按服务器本地时区判断窗口，跨时区玩家整整差一天；角色删除重建后解锁记录丢了，同一个成就又发一次奖励；序列成就按编号字符串排序，十排在九前面，第三阶段永远解锁不了；前置成就用集合去重，同一父节点下两个子成就只算一个；事件乱序到达，后到的旧事件把进度覆盖成更小的值；批量补发事件没有按发生时间排序，进度先加后减；团队成就把队友的击杀记到队长头上，队长一个人解锁了全队进度。achievement_criteria_eval.py 的 AchievementCriteriaEval 负责条件解析、进度累加、去重和解锁判定，四条调用路径共用同一份进度表。硬门禁一：同一成就对同一角色只能解锁一次，重复事件按 ACH_DUP_SUPPRESS 忽略，奖励只发一份。硬门禁二：进度只允许单调递增，赛季重置以外的回退按 ACH_PROGRESS_REGRESS 拒绝写入。硬门禁三：隐藏成就的条件文本不得出现在任何对外查询里，泄露按 ACH_HIDDEN_LEAK 处理。明天上午运营要拿新的解锁曲线做汇报。

## 运行方式
```bash
python -m pytest tests -q
```

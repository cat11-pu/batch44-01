# GSB Bugfix Task
## 题面
赛季末冲分那晚，排行榜上冒出十几个零败场账号，安全组把结算包抓下来一看，签名只覆盖了玩家编号，比分和时长全是裸的。客户端上报的击杀数和服务端事件对不上也被采信；同一份结算包可以重放，同一场对局结算两次；投降方和胜利方各提交一份结果，两份都入库；掉线判负后玩家重连再提交胜利，覆盖原结果；伤害用客户端累计值，改包就能刷出天文数字，结算界面还真按这个发奖；三十秒内结束的对局照常发全额经验和段位分；五人对局三人掉线仍按完整对局结算；签名只覆盖玩家编号，改掉比分之后签名照样通过；结算时间戳乱序，旧对局覆盖新段位；平局双方都扣分，谁也不加分；重赛对局被当成正常对局计入段位；结算失败没有重试，玩家分数直接丢一场，申诉也查不到对局。match_result_verifier.py 的 MatchResultVerifier 管事件聚合、签名校验和幂等结算，所有上报都要落到同一份对局事实表。对局事件、结算包和段位变更要能按对局编号串起来，缺任何一环都不许计分，客服能一眼看到卡在哪一步。三条验收硬线：结算以服务端事件流为唯一事实来源，客户端字段只作校验，偏差按 RESULT_CLIENT_MISMATCH 拒绝；每场对局只能结算一次，重放按 RESULT_REPLAY 幂等丢弃并保留原结果；签名必须覆盖对局编号、双方、比分、时长和结束原因，缺字段按 RESULT_SIG_SCOPE 失败。对局事实表要保留到赛季结束。明天赛季结算，这套校验必须先上线。

```bash
python -m pytest tests -q
```

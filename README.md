# GSB Bugfix Task
## 题面
云平台上线即时提权后，审计发现一张审批单被用了四次，数据库管理员权限在周末一直没回收。平台组原本想用短时授权替代常驻管理员，审批流上线两周就发现回收链路根本没人验证。审批只绑申请单号，不绑具体资源和角色，换成另一个生产库照样能激活；提权时长到期不撤销，会话一直保留管理员组，第二天还能继续操作；同一审批并发激活两次，生成两套凭据；审批人可以批自己的申请；紧急账号绕过审批，且没有到期时间；云上角色撤销接口失败后不重试，权限残留到下一次人工巡检；申请单可以转给同事，审批链对不上；申请 DBA 却授予了超级管理员；紧急撤销只清本地缓存，下游会话仍有效，网关侧还能继续用旧凭据；到期时间按申请人本地时区算，跨时区早关或晚关；被拒申请换个审批人重新提交就能过；审计只记审批动作，不记实际激活和回收。审批流和云平台 IAM 之间只靠一个定时任务对账。jit_elevation_broker.py 的 JitElevationBroker 负责审批、时限、紧急通道、权限回收和对账。到点必须撤销全部下游会话和角色，失败要重试并记 JIT_REVOKE_FAILED；自批必须拒绝并记 JIT_SELF_APPROVAL；审批单只能消费一次且绑定资源与角色，重放报 JIT_APPROVAL_REPLAY，回收结果要写回审批单，告警要带审批单号。等保访谈下周开始，审计组明天要抽查最近二十张审批单，平台组今晚要先把紧急通道停掉。

## 运行方式
```bash
python -m pytest tests -q
```

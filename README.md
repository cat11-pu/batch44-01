# GSB Bugfix Task
## 题面
服务网格换上 SPIFFE 工作负载身份后，滚动发布时一半服务互相认证失败，老证书还在继续用。边车版本跨了三个大版本，行为还不完全一致。轮换时私钥复用，旧 SVID 的私钥直接给新证书；信任包更新不是原子替换，新旧根同时存在导致验签随机失败；使用前不检查 SVID 有效期，过期证书继续发起 mTLS；JWT-SVID 不校验受众，拿给 A 服务的令牌能调 B；工作负载证明只看 UID，同机任意进程都能领到身份；新 SVID 先于信任包下发，对端全部拒绝；边车缓存旧 SVID 不刷新，轮换后一直用旧证书；SPIFFE ID 路径不做归一，大小写和上级目录变体能冒充；信任包接口接受过期根证书；并发轮换生成两张同序列号证书，吊销时只删一张；吊销列表没有下发，泄漏的证书继续可用；节点时钟偏差导致新证书一上线就被判未生效。spiffe_svid_rotator.py 的 SpiffeSvidRotator 负责 SVID 签发、信任包、吊销和序列号去重。证书过期或信任包不匹配必须失败关闭并记 SPIFFE_SVID_INVALID；新 SVID 必须等信任包确认后才能启用，否则报 SPIFFE_BUNDLE_STALE；工作负载证明必须精确匹配选择器，只对 UID 的按 SPIFFE_ATTESTATION_WEAK 拒绝，并保留旧证书指纹供审计。网格里跑着支付和风控，证书一乱就是全站 503。

## 运行方式
```bash
python -m pytest tests -q
```

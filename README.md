# GSB Bugfix Task
## 题面
运维终端统一启用 polkit 后，普通账号能直接挂载加密盘，安全基线扫描给了高危。终端管理平台把规则分三段下发，安全组只看了最后一段就签了字，扫描报告已经挂在内网首页，规则文件和动作文件还分散在三个目录。多条 JS 规则顺序不固定，后加载的 allow 盖住 deny；subject 的 local 和 active 标志直接信客户端上报；动作名用通配匹配，一个规则放开了整类操作；未知动作默认返回 yes，新装的组件直接放行；授权结果不返回 details，前端默认点确认；管理员组只匹配主组，附加组用户被误判；给一个用户开的例外覆盖了全组；认证代理缓存了上一个动作的授权；规则热加载时读到半套规则；动作文件缺失时按允许处理；异步授权期间进程号被复用，权限给了新进程；授权撤销后正在执行的操作继续跑完。polkit_rule_evaluator.py 的 PolkitRuleEvaluator 负责规则求值、主体校验、授权缓存和动作文件回退。deny 必须无条件压过 allow，与规则顺序无关，否则记 POLKIT_DENY_WINS；未知动作必须默认拒绝并记 POLKIT_UNKNOWN_ACTION；授权必须绑定主体进程号和启动时间，复用按 POLKIT_SUBJECT_REUSED 拒绝，拒绝时要给出命中的规则文件。这批终端在营业厅前台，用户点一下就能挂盘，影响太坏，运维准备先把挂载动作全部收回到管理员组。

## 运行方式
```bash
python -m pytest tests -q
```

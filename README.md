# GSB Bugfix Task
## 题面
云存档上线一周，论坛里开始出现整段进度消失的帖子，玩家把两台设备的存档截图并排贴出来，时间线一眼就能看出来。两台设备各自离线玩了几小时，上传时后传的整份覆盖先传的；版本号用设备时间戳，平板时钟慢一天，旧档把新档盖掉；合并时任务进度取较大值、物品取较小值，出现有任务没奖励；云端下载失败直接回退到空档，玩家一进游戏从头开始；上传中断留下半份文件，下次加载直接报损坏，玩家只能删档重开；本地缓存和云端的存档槽编号错位，槽二读到槽三；玩家删档后云端旧档又被自动拉回来；换设备后存档密钥解不开，界面显示存档损坏；多槽位合并只处理了第一个槽，其余槽原样丢弃；自动存档和手动存档混在同一条版本链上互相覆盖；崩溃恢复没有检查点，回滚一次丢半小时进度；跨区账号迁移后存档归属还挂在旧账号上。save_cloud_merge.py 的 SaveCloudMerge 管版本链、冲突合并和原子落盘，本地缓存只作为加速层。版本链上每个节点要记录设备、时间和内容摘要，冲突时能指出是哪两个字段不一致。硬要求：存档必须整份原子提交，半份按 SAVE_PARTIAL 拒绝加载并回退上一份有效档；冲突必须按字段级规则合并并留下可审计记录，静默整份覆盖按 SAVE_CLOBBER 失败。第三条是版本比较必须用单调逻辑版本而非设备时间，时钟回拨不影响结果，违反报 SAVE_CLOCK_TRUST。云端和本地只保留一份权威副本，别再互相覆盖。下周开跨平台测试，丢档一次都输不起。

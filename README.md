# GSB Bugfix Task
## 题面
限时商店改版后，玩家发现同一件折扣商品一天能买三次，运营的库存表对不上消耗，活动预算提前两天用完。每日轮换按服务启动时间算，重启一次商店就刷新一次；跨日重置把所有周期都清了，周限购跟着每日一起重置；夏令时切换那天商品刷新了两次，多出一轮限购；玩家在刷新瞬间下单，钱扣了商品已经下架；刷新券能刷出已经买满限购的商品；轮换池按浮点权重累加，最后一档商品永远刷不出来，概率公示成了摆设；同一件商品在两个货架同时出现，价格还不一样；刷新后价格缓存没失效，界面显示旧价按新价扣款；活动结束后活动商品仍然可以购买；限购按角色计数，同账号换个角色就能继续买，黄牛一个人扫空整服；商城和兑换商店共用库存，一边买空另一边；离线玩家跨日后上线看到的还是昨天的货架。shop_rotation_clock.py 的 ShopRotationClock 管周期键、货架生成和限购，活动配置和常驻配置分开加载，三类周期的边界要能被运营手动核对。货架的每一轮生成都要留快照，玩家看到的价格和限购必须和快照一致，下单时再校验一次。三条硬门禁：每日、每周、活动三类周期必须用独立周期键，互不重置，串期按 SHOP_PERIOD_MIX 失败；刷新与购买必须原子，扣费成功后商品仍在货架，否则按 SHOP_RACE 回滚；限购按账号维度计数且可由流水重放，重放不一致报 SHOP_QUOTA_DRIFT。刷新券的消耗也要能追到具体账号。双十一活动明天预热，货架不能再串。

## 运行方式
```bash
python -m pytest tests -q
```
